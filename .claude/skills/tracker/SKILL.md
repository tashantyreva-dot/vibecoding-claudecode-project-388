# tracker

Оркестратор поверх [`extract-price`](../extract-price/SKILL.md): собирает объявления
о продаже **MINI Countryman** (б/у) со всех источников, сравнивает с прошлым прогоном
и уведомляет в Telegram о **новых** и **подешевевших** объявлениях под бюджет.

Данные (конфиг, история прогонов, правила) живут в отдельном GitHub-репозитории
**`tashantyreva-dot/tracker-data`** и читаются/пишутся через **GitHub MCP**.

## Устройство

Скилл состоит из двух частей — потому что Node не умеет вызывать MCP, а MCP-инструменты
доступны только агенту:

| Часть | Кто исполняет | Ответственность |
|-------|---------------|-----------------|
| **этот SKILL.md** | Claude (headless) | чтение/запись GitHub через MCP, оркестрация |
| [`scripts/run-tracker.js`](../../../scripts/run-tracker.js) | Node | обход источников, сборка прогона, diff, вызов доставки |
| [`scripts/send.py`](../../../scripts/send.py) | Python (stdlib) | отправка готового текста в Telegram |

`run-tracker.js` работает с **локальными файлами**: Claude выкачивает конфиг и прошлый
прогон через GitHub MCP во временные файлы, запускает скрипт, затем забирает
получившийся прогон и кладёт его в GitHub через MCP.

Доставка вынесена в отдельный `send.py` (только стандартная библиотека, `urllib`):
`run-tracker.js` не дублирует HTTP-логику, а вызывает `python send.py "<текст сводки>"`.
`chat_id` берётся из `notify.yaml` и передаётся в `send.py` через переменную окружения
`TELEGRAM_CHAT_ID`; токен — `TELEGRAM_BOT_TOKEN` — наследуется из окружения.
`send.py` можно тестировать отдельно: `python send.py "тест"` → в ответ печатает
`Отправлено.` и шлёт сообщение (нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`
в окружении или в `.env` рядом со скриптом).

## Файлы в `tracker-data`

- `products.yaml` — источники (`sources[].id`, `.url`) и `search.max_price`.
- `notify.yaml` — `telegram.chat_id` (секретом не является). **Токен бота там НЕ хранится.**
- `KNOWLEDGE.md` — правила значимости и формат уведомления.
- `runs/YYYY-MM-DD.json` — история прогонов (по одному файлу на дату).

## Секрет

Токен Telegram-бота читается **только** из переменной окружения `TELEGRAM_BOT_TOKEN`
и никогда не хранится в репозитории и не хардкодится. Если есть значимые изменения,
но токен не задан, `run-tracker.js` **явно падает** (код выхода `2`), а не молчит.

## Порядок работы (что делает Claude при запуске)

1. **Прочитать конфиг** через GitHub MCP (`get_file_contents`, owner `tashantyreva-dot`,
   repo `tracker-data`): `products.yaml`, `notify.yaml`. Сохранить их в локальные
   временные файлы.
2. **Найти прошлый прогон.** Прочитать каталог `runs/` (`get_file_contents` path `runs`).
   Взять файл с **самой поздней датой строго раньше сегодняшней** (не обязательно
   вчерашний — на случай пропущенных запусков). Игнорировать `.gitkeep`. Скачать его
   содержимое в локальный файл. Если подходящего файла нет — прогон **первый в истории**
   (передать `--prev ""`).
3. **Запустить оркестратор** (переменная `TELEGRAM_BOT_TOKEN` должна быть в окружении):

   ```bash
   node scripts/run-tracker.js \
     --products <локальный products.yaml> \
     --notify   <локальный notify.yaml> \
     --prev     <локальный прошлый-прогон.json | ""> \
     --out      <локальный новый-прогон.json>
   ```

   Скрипт сам обойдёт источники через `extract.js`, соберёт прогон, посчитает diff и
   при значимых изменениях отправит Telegram. Он пишет прогон в `--out` и печатает в
   **stdout** JSON-сводку (`diff`, `telegram`, `run`); ход выполнения — в stderr.
4. **Записать прогон в GitHub** через MCP (`create_or_update_file`,
   path `runs/<сегодня>.json`, branch `main`) — содержимое берётся из файла `--out`.
   Если файл за сегодня уже существует, передать его `sha` (перезапись).
5. **Отчитаться** пользователю: статусы источников (`ok`/`error`), число значимых
   изменений, был ли отправлен Telegram.

> Первый прогон, дифф и запись в GitHub с побочными эффектами (Telegram, коммит) —
> при интерактивной проверке сначала показывай пользователю собранный прогон и текст
> сообщения, и только после подтверждения пиши в GitHub / шли Telegram. Для этого у
> скрипта есть флаг `--dry-run`: он всё считает и собирает сообщение, но **не** шлёт
> Telegram.

## Правила значимости (реализованы в `computeDiff`)

Диффать источник можно, **только если у него `status: "ok"` и в текущем, и в прошлом
прогоне** — иначе упавший сегодня источник ложно выглядел бы как «все объявления
пропали». Для пары «ok/ok» сравнение идёт по `url` (уникальный ключ):

| Ситуация | Значимо? | В Telegram |
|----------|:--------:|-----------|
| `url` новый (не было в прошлом прогоне) | да | 🆕 |
| `url` тот же, `price` **ниже** | да | 📉 (с «было …») |
| `url` тот же, `price` вырос | нет | — |
| `url` пропал (машину сняли/купили) | нет | — (логируется в `diff.disappeared`) |

**Fresh-старт.** Если прошлого прогона нет вообще — это не «0 изменений», а первый
прогон: все найденные объявления показываются как есть, с пометкой «первый прогон».

**Нет значимых изменений → ничего не шлём.** Пустое сообщение и «изменений нет» не
отправляются.

## Формат прогона (`runs/YYYY-MM-DD.json`)

```json
{
  "date": "2026-08-13",
  "sources": [
    {
      "id": "rolf-used-mini",
      "url": "https://www.rolf.ru/cars/used/mini/",
      "status": "ok",
      "listings": [
        { "price": 1100000, "year": 2012, "mileage": 142632, "url": "https://..." }
      ]
    },
    {
      "id": "autoru-countryman",
      "url": "https://auto.ru/moskva/cars/mini/countryman/all/",
      "status": "error",
      "error": "капча заблокировала интерактивный режим",
      "listings": []
    }
  ]
}
```

`status` обязателен для каждого источника. У `error`-источника `listings` всегда пуст,
и он не участвует в диффе.

## Формат уведомления (из `KNOWLEDGE.md`)

```
🚗 Значимые изменения — MINI Countryman (13.08.2026):

🆕 rolf.ru — 1 100 000 ₽, 2012 г., 142 632 км
   https://...

📉 major-expert.ru — 1 150 000 ₽ (было 1 400 000 ₽), 2015 г., 149 027 км
   https://...
```

Первым блоком идут новые (🆕), затем подешевевшие (📉). `year`/`mileage`, если не
распарсились, опускаются.

## Коды выхода `run-tracker.js`

| код | значение |
|-----|----------|
| 0 | прогон отработал (в т.ч. если часть источников упала — это не фатально) |
| 1 | фатальная ошибка вызова/конфига (нет аргументов, битый `products.yaml`) |
| 2 | нужно было отправить Telegram, но `TELEGRAM_BOT_TOKEN` не задан / ошибка сети |

Падение отдельного источника (капча/таймаут/смена вёрстки) — **не** фатально: источник
получает `status: "error"`, прогон продолжается, а `extract-price` не выдаёт пустой
результат за «ничего не нашлось» (см. его коды выхода).
