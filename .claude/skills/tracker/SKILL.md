# tracker

Собирает объявления о продаже **MINI Countryman** (б/у) со всех источников из
[`products.yaml`](../../../products.yaml) через [`extract-price`](../extract-price/SKILL.md),
сравнивает с прошлым прогоном и уведомляет в Telegram о **новых** и **подешевевших**
объявлениях под бюджет.

Никакой отдельной оркестрации на Node здесь больше нет: раньше `github-sync.js` ходил
в GitHub REST API, а `run-tracker.js` обходил источники, считал diff и слал уведомление —
всё это делает сама сессия Claude обычными инструментами (чтение файлов, `git`, Bash)
по шагам ниже. Единственный оставшийся вспомогательный код — `extract.js` (per-source
скрейпинг, см. [`extract-price`](../extract-price/SKILL.md)) и [`send.py`](../../../send.py)
(доставка в Telegram): и то, и другое обёрнуто во внешний headless-браузер/HTTP-запрос,
который агенту проще вызвать готовым скриптом, чем переписывать самому.

## Репозитории

- **`tashantyreva-dot/vibecoding-claudecode-project-388`** (публичный, этот репозиторий) —
  реализация: `products.yaml`, `KNOWLEDGE.md`, скиллы, `send.py`. Он же авто-созданный
  Hexlet-репозиторий проекта (в нём лежит `.github/workflows/hexlet-check.yml`).
- **`tashantyreva-dot/tracker-data`** (приватный) — **только** история прогонов
  (`runs/YYYY-MM-DD.json`), больше ничего.

С обоими репозиториями работай обычным `git` (`pull`/`add`/`commit`/`push`), без
самописных REST-обёрток. Этот репозиторий — текущая рабочая копия (CWD). Локальная
копия `tracker-data` должна быть склонирована рядом, в соседней папке:
`<этот репозиторий>/../tracker-data`. Если её там нет — склонировать один раз:
`git clone https://github.com/tashantyreva-dot/tracker-data.git ../tracker-data`.

> **Секреты.** Headless-сессия Claude Code блокирует любую Bash/PowerShell-команду, в
> тексте которой видна подстановка переменной окружения ($VAR, ${...}, $env:VAR) — это
> защита от утечки секретов и её не обходит `--dangerously-skip-permissions`. Это
> касается и `git`: URL/токен GitHub не должны появляться в тексте команды —
> аутентификация должна быть настроена заранее (credential helper / Git Credential
> Manager / SSH-ключ), а не через `https://$GITHUB_PAT@github.com/...` в команде.
> Токен Telegram-бота и `chat_id` — только `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в
> окружении процесса, тоже без подстановки в тексте команд; `send.py` сам их прочитает.
>
> GitHub MCP (в т.ч. OAuth-коннектор "claude.ai Github") в headless-режиме не работает —
> требует согласия через веб-интерфейс claude.ai, которое некому дать без интерактива.
> Поэтому — только `git`.

## Порядок работы

1. **Синхронизировать оба репозитория.**
   - Здесь: `git pull` — актуальные `products.yaml`, `KNOWLEDGE.md`, скиллы.
   - В `../tracker-data`: `git -C ../tracker-data pull` (или склонировать, если папки
     ещё нет — см. выше).
2. **Прочитать `products.yaml`.** Файл маленький и читаемый — отдельный парсер не
   нужен, читай его как обычный текст: `search.max_price` (бюджет) и список
   `sources[]` (`id`, `url` для каждого источника).
3. **Найти прошлый прогон.** В `../tracker-data/runs/` — файл с самой поздней датой
   строго раньше сегодняшней (не обязательно вчерашний, на случай пропущенных
   запусков). Если файлов ещё нет вообще — это fresh-старт (см. правила значимости).
4. **Обойти источники.** Для каждого `sources[]`:
   `node .claude/skills/extract-price/extract.js <url>`
   (коды выхода см. в [`extract-price`](../extract-price/SKILL.md): 0 — успех,
   1/2/3 — ошибка). Для каждого источника сохрани
   `{ id, url, status: "ok"|"error", listings, error? }` — упавший источник **не**
   считается «пустым результатом» и не участвует в диффе (см. ниже).
   Отфильтруй `listings` по `search.max_price` из `products.yaml` ещё раз — он
   авторитетный источник бюджета, даже если `extract.js` уже фильтрует по своему.
5. **Собрать прогон** `{ date, sources }` (формат — см. ниже) и **сразу записать**
   его в `tracker-data`: `runs/<сегодняшняя дата>.json`, затем
   `git -C ../tracker-data add/commit/push`.
6. **Посчитать diff** с прошлым прогоном по правилам из
   [`KNOWLEDGE.md`](../../../KNOWLEDGE.md) (кратко — в таблице ниже). Списки
   объявлений короткие (после фильтра по цене — единицы на источник), так что
   сравнение по `url` вручную, без отдельного скрипта, безопасно и не рискует
   что-то пропустить.
7. **Собрать текст уведомления**, если значимые изменения есть — формат ниже.
   Если значимых изменений нет — Telegram не шлём, это ожидаемо, не ошибка.
8. **Отправить в Telegram**, если есть текст: `python send.py "<текст>"` (нужны
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в окружении процесса — `send.py`
   прочитает их сам). Если переменных нет, `send.py` сам упадёт с понятной
   ошибкой — не пытайся передать токен/chat_id как-то ещё.
9. **Отчитаться** пользователю: статусы источников (`ok`/`error`), число значимых
   изменений, был ли отправлен Telegram.

> При интерактивной проверке (не cron) — сначала покажи пользователю собранный
> прогон и текст уведомления и дождись подтверждения, прежде чем писать в
> `tracker-data`/слать Telegram.

## Правила значимости

Диффать источник можно, **только если у него `status: "ok"` и в текущем, и в прошлом
прогоне** — иначе упавший сегодня источник ложно выглядел бы как «все объявления
пропали». Для пары «ok/ok» сравнение идёт по `url` (уникальный ключ):

| Ситуация | Значимо? | В Telegram |
|----------|:--------:|-----------|
| `url` новый (не было в прошлом прогоне) | да | 🆕 |
| `url` тот же, `price` **ниже** | да | 📉 (с «было …») |
| `url` тот же, `price` вырос | нет | — |
| `url` пропал (машину сняли/купили) | нет | — (можно упомянуть в отчёте пользователю) |

**Fresh-старт.** Если прошлого прогона нет вообще — это не «0 изменений», а первый
прогон: все найденные объявления показываются как есть, с пометкой «первый прогон».

**Нет значимых изменений → ничего не шлём.** Пустое сообщение и «изменений нет» не
отправляются.

## Формат прогона (`runs/YYYY-MM-DD.json`)

```json
{
  "date": "2026-08-13",
  "sources": [
    {
      "id": "rolf-used-mini",
      "url": "https://www.rolf.ru/cars/used/mini/",
      "status": "ok",
      "listings": [
        { "price": 1100000, "year": 2012, "mileage": 142632, "url": "https://..." }
      ]
    },
    {
      "id": "autoru-countryman",
      "url": "https://auto.ru/moskva/cars/mini/countryman/all/",
      "status": "error",
      "error": "капча заблокировала интерактивный режим",
      "listings": []
    }
  ]
}
```

`status` обязателен для каждого источника. У `error`-источника `listings` всегда пуст
и он не участвует в диффе.

## Формат уведомления (из `KNOWLEDGE.md`)

```
🚗 Значимые изменения — MINI Countryman (13.08.2026):

🆕 rolf.ru — 1 100 000 ₽, 2012 г., 142 632 км
   https://...

📉 major-expert.ru — 1 150 000 ₽ (было 1 400 000 ₽), 2015 г., 149 027 км
   https://...
```

Первым блоком идут новые (🆕), затем подешевевшие (📉). `year`/`mileage`, если не
распарсились, опускаются.

Падение отдельного источника (капча/таймаут/смена вёрстки) — **не** фатально для
прогона: источник получает `status: "error"`, прогон продолжается по остальным, а
`extract-price` не выдаёт пустой результат за «ничего не нашлось» (см. его коды выхода).
